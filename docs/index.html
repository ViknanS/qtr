Rank rollouts, not raw scores.

qqr trains open-ended LLM agents with ArenaRL: every group of rollouts plays a tournament judged pairwise by an LLM, and the final standings become the reinforcement-learning advantage. It plugs into slime and runs tools through the Model Context Protocol.

This site documents the ViknanS/qtr fork. qqr and the ArenaRL, ARISE-RL, RTI and SecRespond research are by the authors of Alibaba-NLP/qqr, released under Apache-2.0.

Why tournaments

Open-ended tasks such as trip planning or deep research have no single correct answer. When an LLM judge scores each rollout on its own, the scores bunch together and the group advantages flatten out, so learning stalls. The ArenaRL paper calls this discriminative collapse. Comparing rollouts against each other keeps the signal sharp.

Pointwise scoring

A judge gives each of 8 rollouts a 1–10 score. Most land on 7 or 8.

Round-robin tournament

The same rollouts compared head to head, ranked by wins.

Illustration computed in your browser from fixed example scores with the same rules as qqr/reward_models/arena. Not a training result.

Five tournament topologies

Anchor-based, round-robin, Swiss system, double elimination and seeded single elimination, each turning pairwise judgements into group-normalised rewards.

Tools over MCP

Environments are ordinary MCP servers (maps, web search, transport, τ²-bench domains, Claw-Eval services), with result caching and per-server concurrency limits.

Built on slime

Uses slime's Megatron training and sglang rollout engine. qqr adds the agent rollout loop and rewards without forking the trainer.

ARISE-RL self-evolution

A Generator writes tasks and rubrics near the Solver's ability boundary; the Solver learns from rubric rewards with reward-gated self-distillation.

RTI interventions

When every rollout in a group fails, a judge–corrector–post-check pipeline repairs the decisive step, gated by perplexity and reweighted per token.

Benchmarks included

Open-Travel, DeepResearch, ECR-Bench, Navigation, τ²-bench, Claw-Eval-Hard and SecRespond data ship with the repository. See the list.

Everything here is a simulation with a synthetic judge. It shows how each topology turns comparisons into rewards; it is not an LLM, not model training and not a benchmark result. Published results are in the papers.

    Runs on a laptop (macOS or Linux)

    • All five tournament reward models, with any OpenAI-compatible judge
    • MCP tool servers and the caching MCP client
    • Qwen3 / Qwen3.5 tool-call parsers, data utilities, RTI helper maths
    • Offline demo: python -m qqr.demo; environment check: python -m qqr.doctor
    • The full pytest suite, with mocked services and no API keys

    Needs a Linux GPU node

    • Every training launcher in scripts/ (8 NVIDIA GPUs per node by default)
    • slime v0.3.1 with Megatron-LM, sglang and Ray, plus the RG-SED patch for ARISE-RL
    • Agent rollouts (qqr.rollout) and RTI reference scoring, which call sglang
    • Model checkpoints such as Qwen3-8B or Qwen3.5-9B
    • API credentials for judges and tools, listed in .env.example

    Install and use

    Start on any machine with the core package and the offline demo. Move to a GPU node with slime when you want to train.

    On your laptop

    # Python 3.11+ (asyncio.TaskGroup)
git clone https://github.com/ViknanS/qtr.git
cd qtr
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,tools]"

python -m qqr.doctor     # what can run here
python -m qqr.demo       # tournaments, mock judge
pytest                   # offline test suite

    Use a tournament in your own code

    from qqr.reward_models import get_reward_model
from qqr.schemas import LLMRewardModel

class MyJudge(LLMRewardModel):
    async def compute(self, prediction, reference, query):
        ...  # call your LLM, compare the two trajectories
        return {"prediction": 7.0, "reference": 5.5}

arena = get_reward_model("swiss")(MyJudge(llm=None))
rewards = await arena(predictions=trajectories, query=query)

    Train on a GPU node

    # 1. slime at the paired version
git clone https://github.com/THUDM/slime.git
cd slime && git checkout v0.3.1   # follow slime's Quick Start

# 2. qqr
git clone https://github.com/ViknanS/qtr.git
cd qtr && pip install -e ".[tools,examples]"

# 3. credentials (never commit .env)
cp .env.example .env && $EDITOR .env
set -a && source .env && set +a

# 4. ArenaRL on Open-Travel
bash scripts/travel/run-qwen3-8B.sh

    Launchers stop leftover sglang, Ray and training processes before they start, so they refuse to run unless the host is Linux with nvidia-smi. ARISE-RL also needs patches/slime-rg-sed-v0.3.1.patch applied to slime. Version pairs are listed in the compatibility table.
